# Changes from the original

The rebuild stays as close to the original code as possible and changes it only
to fix what (A) cannot run on macOS or modern Windows, or (B) breaks on modern
Windows without helpers such as DDrawCompat, plus real bugs that break play
(Owen, 2026-10-19), marked `FIX (bug)`, and the copy-protection and
anti-tamper traps (Owen, 2026-10-20, `protection.md`), marked `FIX (trap)`.
Each change is also marked `FIX` in the code next to the original address.

## The bug fixes switch

`zfix::options().bugs` holds every play-changing `FIX (bug)`: a player turns
them all off with `bugfixes=0` in mw3.cfg or `mw3 --original` (which wins over
mw3.cfg), and mw3 says so at the start (Owen, 2026-10-30; the probes run with
it off, so the differential tests check the original's path). Off means the
original's play: each fix that CHANGES.md lists under "Bug fixes that change
play" goes back to the exe's way, except the frame-rate ones. What stays on
either way:
- the platform fixes the game needs to run at all, FIX (A) and FIX (B):
  `nested_lock`, `any_resolution`, the 53-bit rounding (`fpu53`), and every
  unflagged (A)/(B) row below;
- the frame timings, `per_second` (Owen, 2026-10-20: per-frame steps go to
  time at the 30 fps pace; not a bug fix and not switched);
- the crash and memory fixes, where the exe would crash, read freed or stray
  memory or loop for ever (a null checked, a buffer bounded, a freed record
  kept: the vehicles' fire floor, the craters' overlap test, an animation
  instance's borrowed tree), since the original's behaviour there is no
  behaviour to restore.

Folded into `bugs` on 2026-10-30 (until then on always):
the deep-water curve (its own `deep_water` until then), the heat-sink
critical's callout, the particle fade-in typo, the animations' last-def
search, and the animations' missing-prerequisite fix (its own
`fix_prerequisites` remains as a test seam, acting only with `bugs`). The
in-game options screen has no line for it: its dialog comes from the
player's own data (reader.zbd's dlgGameOptions), which the rebuild does not
change.

Notes on the fixes:

- Frame clock at 24-bit: in play the x87 runs at single precision (CLAUDE.md),
  so the original rounds `ticks * 0.001` to a float before the subtraction:
  frame times jitter by about 0.06 ms once the game has run some minutes, and
  a zero-millisecond frame comes out as about 1.6e-6 s. The port keeps double
  (as the 64-bit reading below), part of the frame clock fix; ztimer's test
  passes at 64 bits and shows the difference at 24 (`MW3_X87=24`).
- Frame clock: in the original the product `ticks * 0.001f` stays on the x87
  stack at 80 bits while it is stored to `now_s` and subtracted from `prev_s`,
  so `raw_dt` is rounded once, from the unrounded product. The port computes it
  in double, which gives the same result while ticks stay under 2^29 (six days).
- zReader: the original's `malloc(count * 8)` for a list stored with count 0
  also wrote slot 0 past the block; the spare slot covers that too.

Noted but not yet ported:

- The app constructor (0x47f7a0) quits when the DirectX version reads below 6.
  Whether modern Windows reports this correctly is unchecked; the rebuild asks
  its `directx_version` hook and ignores the answer.

- **The AppImage's launcher outlives the game** (FIX (A), ours; `Launcher::watch_game`): closing it unmounted the image under the running game, SIGBUS at the end of the intro. `docs/linux.md`, Packaging.
- **A crash says why** (ours; `crash_report.cpp`): the log and a box. `docs/program.md`, The log.
- **An install in any letter case** (FIX (A); `zutl::any_case`): the original's names meet Windows, where case does not matter. On a case-sensitive disk each part of a path is taken exact if it is there, else by its letters; each mount keeps its place in the order. `docs/assets-layer.md`.
